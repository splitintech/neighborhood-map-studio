# Existing SplitIn public pages

`public-layers.ts` mounts the same renderer used by the editor onto an existing Leaflet map. It fetches the published-only projection from Supabase, independently of Daytona. Use the public Supabase legacy anon JWT key, **never** the service-role key. The migration exposes this single read function; drafts, originals, sessions and all writes remain inaccessible to anonymous clients.

1. Apply `integrations/splitin.patch` to the isolated SplitIn checkout. It vendors the current `shared/` contracts/renderer and this adapter into the existing discovery-map package, adds the public CSS, and wires both public entrypoints. Import the shared layer CSS once alongside the existing map CSS (the patch folds it into the existing discovery-map stylesheet).
2. After the existing map-consent gate and map initialization, call `attachPublishedLayers` with existing Leaflet/map handles and canonical business IDs (`placeIdentity(city, place)`), source-backed locations, name and category. Do not calculate replacement coordinates. Supply `setBusinessSuppressed(id, suppressed)` as an additional condition in the existing marker filter, and `selectBusiness(id)` using the existing map/list selection handler. This prevents duplicate markers while respecting business visibility.
3. Configure the browser-safe `PUBLIC_MAP_STUDIO_SUPABASE_URL` and `PUBLIC_MAP_STUDIO_SUPABASE_ANON_KEY` values plus one exact per-map flag (`PUBLIC_MAP_STUDIO_SAN_FRANCISCO_MISSION` or `PUBLIC_MAP_STUDIO_BOSTON_BACK_BAY`). The adapter recognizes only the exact `/blog/guides/{pilot-key}/places/` routes; category directories stay disabled unless an explicit matching `data-map-studio-key` is supplied. Keep existing routing, cards, structured data, map/list selection, filtering, sources, attribution and OpenFreeMap basemap.
4. Dispose the returned renderer when the parent map unmounts. Recreate on a different map. When category/search filters change, call `update` with the current document, assets and only the businesses currently visible in those filters. Load each manifest once on map opening; page reload sees publication/rollback immediately through the durable SQL pointer.
5. Permit the configured Supabase origin in the public site's `connect-src` and `img-src` CSP. Only public hashed WebP assets are loaded.
6. After staging acceptance, enable `public_delivery_enabled` for that map through an administrator migration. Both switches default off.

The application remains entirely in `open-internal-tools`; the patch is the reviewable public-page wiring artifact. Browser regression evidence and enabling the database projection remain deployment work.
